# database/

Readable references and read-only SQL for the PostgreSQL 16 database. The **source of truth is the
Alembic migrations** in `backend/alembic/versions/` (head `0023`); nothing here is applied by Docker.

| File | What |
| --- | --- |
| `schema.sql` | The whole schema, **generated** with `pg_dump --schema-only` at revision 0023. No rows. Its header says how to regenerate it after each migration. Do not edit it by hand. |
| `ERD.md` | Entity-relationship diagrams and the reasons behind the tables |
| `EVENT_CONTRACT.md` | The payload of every event Unity sends (`session_events.payload`) |
| `verify_*.sql` | Read-only checks of a session or a milestone. `autorun` runs `verify_eeg.sql`, `verify_adaptation.sql`, `verify_projection.sql` and `p0_j3_fallback_check.sql` after each session |
| `check_loop.sql` | Read-only check of the adaptation loop of the latest `BEHAVIOR_ADAPTIVE` session |
| `seed_kanji_items.sql` | The `kanji_items` catalogue, generated by `tools/kanji_seed_sql.py`; apply it after `alembic upgrade head` |
| `backfill_*.sql` | Maintenance scripts that **write** (idempotent): `completed_at` for old sessions, and the schema v1 projection rebuilt from `session_events`. Read their header before running |
| `cleanup_2026-10-17.sql` | A one-off clean-up of 17 Oct 2026 that **deletes** data; kept as history, never run again |

Run a check, read-only, from the repo root:

```powershell
Get-Content database\verify_eeg.sql | docker compose exec -T db psql -U neuroadaptive -d neuroadaptive_vr -v sid=<id prefix>
```

Without `-v sid`, `verify_eeg.sql` reports every session that has an `eeg_sessions` row.

More in the documentation site: `docs/data-model.md`, which also includes `ERD.md` and
`EVENT_CONTRACT.md`.
